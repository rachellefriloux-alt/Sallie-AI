## 8. Platforms & Access

| Source | Content |
|--------|--------|
| Plan | "3 doors into the same house": Desktop, Mobile, Web — all sync to same backend. |
| README | Web App (browser), Desktop App (Windows/macOS/Linux installers), Android App (APK). Backend required first; then choose one or more clients. |

### 8.1 Quick Start (README)

- **Backend**: ./start-sallie.sh or start-sallie.bat; then e.g. python -m uvicorn core.main:app --reload --port 8000.
- **Web**: cd web and npm run dev — http://localhost:3000
- **Desktop**: cd desktop and npm run build:win (or build:mac / build:linux); install from dist/.
- **Android**: cd mobile/android and ./gradlew assembleRelease; install APK; backend URL = computer IP (e.g. http://192.168.1.x:8000).

### 8.2 System Requirements (README)

- **Backend**: Windows 10+, macOS 10.15+, or Linux; 4+ cores (8+ recommended); 8 GB RAM (16 recommended); 20 GB; Python 3.11+; Node 18+; Docker optional.
- **Desktop**: Windows 10 64-bit+; macOS 10.15+; Linux Ubuntu 20.04+.
- **Android**: Android 8.0+; 500 MB; same WiFi as backend.
- **Web**: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+.

## 11. Resilience & Optional Cloud (Azure)

- **Default:** Local-first. Sallie runs on your devices; no cloud required.
- **Optional Azure (or other cloud):** You can deploy Sallie to Azure so she’s available when you have no wifi or power (e.g. access via cellular or from another place). Use Azure as a fallback when local is unreachable.
- **Sync:** Local and cloud instances **stay in sync**. Same Heritage DNA, memories, limbic state, conversation history, and capabilities—one Sallie everywhere. Sync is bidirectional; when local is back online, it reconciles with Azure (or vice versa). Conflict resolution: last-write-wins or Creator-chosen strategy; no silent overwrites of critical state.
- **Priority:** Prefer local when available; use Azure (or cloud) when local is down or unreachable.
